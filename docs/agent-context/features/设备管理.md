# 设备管理

> 一句话：管理员在「系统管理 → 设备管理」里维护设备台账（名称、序列号、地址、固件版本、在离线状态、添加时间），后端是 `/device` 一组 CRUD 接口。

代码在 main 上（提交 cca274d，分支 cox/T-10），已合并。

## 业务规则

### 设备只有六个业务字段，添加时间由系统填

列表与表单覆盖设备名称、设备序列号、设备地址、设备固件版本、在离线状态、添加时间。表单只提交前五个，`createTime` / `createBy` / `updateTime` / `updateBy` 由 MyBatis-Plus 的自动填充写入，前端表单里刻意不出现「添加时间」。

### 在离线状态是 0/1 两态：0 离线、1 在线，默认离线

库里 `online_status char(1) DEFAULT '0'`，列表用两种标签区分（在线用 success、离线用 info），表单用单选默认选「离线」。它是人工维护的字段，不接设备心跳。

### 删除是逻辑删除，空数组删除直接返回成功且不动数据

`del_flag` 带 `@TableLogic`，删除只是置标记，行还在表里。`DELETE /device` 收到空数组时不调 service，直接 `R.ok(true)`，避免一次误触把整表删了。

## 接口和数据

- `GET /admin/device/page`：分页查询，参数 `current`、`size`、`deviceName`、`deviceSerialNo`、`onlineStatus`；返回 MyBatis-Plus 分页对象。
- `GET /admin/device/details/{deviceId}`：按主键取一条。
- `POST /admin/device`：新增，body 为设备对象，`deviceName`、`deviceSerialNo`、`onlineStatus` 必填（`@NotBlank`）。
- `PUT /admin/device`：修改，body 带 `deviceId`。
- `DELETE /admin/device`：body 为 id 数组（`Long[]`），空数组为 no-op。
- 数据表 `sys_device`：主键 `device_id`（雪花 ID），`del_flag` 逻辑删除，`idx_device_serial_no` 是普通索引不是唯一索引。
- 前端封装：`pig-ui/src/api/admin/device.ts`（fetchList / addObj / getObj / delObj / putObj）。

## 已知限制

### 设备序列号没有唯一约束，同序列号可以重复新增

`idx_device_serial_no` 只是普通索引，业务层也没做唯一校验，同一个序列号能建多条记录。删除后重新用同一序列号新增也是允许的——这是当前行为，不是待修的 bug；如果以后要求唯一，得加唯一索引并处理历史重复数据。

## 怎么验证

- 要准备的：管理员账号（角色 1，已授权 2700-2704）；`sys_device` 里有种子 3 条或自建数据；库已执行升级脚本且菜单缓存已清。
- 主要步骤：
  1. 「系统管理」下出现「设备管理」并能打开；浅色/暗黑下文字清晰，表头、分页、按钮样式与岗位管理页一致。
  2. 表格六列齐全；添加时间是 `yyyy-MM-dd HH:mm:ss`；状态是「在线/离线」双色标签；没有 undefined / null / 空列。
  3. 新增两条不同序列号的设备，提示「添加成功」，逐字段核对；F5 后按序列号能搜到；库中 `del_flag='0'`。
  4. 编辑其中一条的地址、固件版本、状态，保存后其它列与其它行都不变；打开编辑后取消，原值仍在。
  5. 单个删除与批量删除两行：确认后行立即消失、总数减少，刷新后按序列号搜不到；同序列号可重新新增成功。
- 自动化测试：前端 `pig-ui/src/views/admin/device/device.spec.ts`（接口路径、六列、两态标签、`v-auth`、i18n key、表单不提交 createTime）；后端 `pig/pig-upms/pig-upms-biz/src/test/java/com/pig4cloud/pig/admin/controller/SysDeviceControllerTests.java`（默认排序、查询条件、空数组删除、save/update 透传）。
