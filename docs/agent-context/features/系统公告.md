# 系统公告

> 一句话：管理员在「系统管理 → 系统公告」里写通知（草稿/已发布/已下线），登录用户首页顶部显示最新一条已发布公告，可以关掉。

代码在 main 上（提交 b7a139a，分支 agent/T-11），已合并。

## 业务规则

### 三种状态：0 草稿、1 已发布、2 已下线

状态是非空单字符，后端用 `@Pattern(regexp="[012]")` 兜住非法值；列表只按三种状态各自渲染标签（已发布 success、草稿 info、已下线 warning），没有 `v-else` 兜底，非法值一个标签都不渲染，绝不会被当成「已发布」。

### 发布时间只由服务端写，请求体里带的 publishTime 一律丢弃

新增时状态缺省为草稿；只有直接建成「已发布」才写 `publish_time = now()`，草稿与下线都写 null。修改时只有「从非已发布变成已发布」的流转才刷新发布时间；改成已下线、改回草稿、或本来就是已发布再保存，都置 null 走 `update-strategy=not_null` 跳过该列，库里原发布时间保留。这样下线一条公告不会把「它什么时候发过」抹掉。

- 来源：pig/pig-upms/pig-upms-biz/src/main/java/com/pig4cloud/pig/admin/service/impl/SysNoticeServiceImpl.java:77-145

- 状态：待确认

### 修改只允许动标题、正文、状态，审计字段交给自动填充

`prepareForUpdate` 只把这三个字段塞进更新对象，其余（发布时间、删除标记、创建人、创建/更新时间）要么由状态流转决定，要么置 null 交给 `MetaObjectHandler`；新增时也会先把请求体里的审计字段清空，防止伪造 `createBy` / `delFlag`。

### 首页公告条只显示最新一条已发布，且取不到就完全不渲染

`GET /notice/latest` 按 `status='1'`、`publish_time desc`、`notice_id desc` 取一条，没有则 `data=null`。首页组件拿不到对象（null、无 noticeId、或这条已被本机关过）就 `v-if` 整体不渲染，**不 import useMessage、不弹任何错误提示**——公告是附加信息，接口挂了不影响首页其它 widget。

- 来源：SysNoticeServiceImpl.java:50-65、pig-ui/src/views/home/notice-bar/index.vue:2,29-39、pig-ui/src/views/home/index.vue:3

### 「关掉」记在本机，按 noticeId 记录，换一条会重新出现

关闭时把 `notice-closed-<noticeId>` 写进本地存储（`Local.set`），下次加载如果本地已记录同一个 noticeId 就不渲染；管理员换一条新公告，noticeId 变了，公告条会重新出现。

### 标题 100 字、正文 2000 字，前后端都卡

后端 `@NotBlank` + `@Size(max=100/2000)`；前端表单 `maxlength` + `show-word-limit` + required 规则，另外补了一条「全是空格也算空」的校验（后端 `@NotBlank` 会拒，前端先一步拦下不发请求）。正文是 `type="textarea"`，纯文本存 text 列，首页用 `whitespace-pre-line` 保留换行。

## 接口和数据

- `GET /admin/notice/latest`：最新一条已发布公告，没发布过时 `data=null`。**没有 `@HasPermission`**，登录即可访问（首页公告条要用）。
- `GET /admin/notice/page`：分页，参数 `current`、`size`、`title`（like）、`status`（eq）；不传排序时默认 `create_time desc`。权限 `sys_notice_view`。
- `GET /admin/notice/details/{noticeId}`：按主键取一条。权限 `sys_notice_view`。
- `POST /admin/notice`：新增。权限 `sys_notice_add`。
- `PUT /admin/notice`：修改，主键不存在返回 `false` 不报错。权限 `sys_notice_edit`。
- `DELETE /admin/notice`：body 为 id 数组，空数组 no-op 返回 true。权限 `sys_notice_del`。
- 数据表 `sys_notice`：`title varchar(100)`、`content text`、`status char(1)`、`publish_time datetime`、`del_flag` 逻辑删除，索引 `idx_status_publish (status, publish_time DESC)`。
- 前端封装：`pig-ui/src/api/admin/notice.ts`（含首页用的 `fetchLatest`）。
- 种子：菜单 2750（系统公告，parent 2000）+ 2751-2754 四个按钮权限，授权角色 1；i18n 77 = `router.noticeManagement`（`pig/db/pig.sql:443,573-577`）。

## 已知限制

### 只显示最新一条，看不到历史公告

首页只取一条，没有「历史公告」入口；旧的已发布公告会被新的顶掉，用户没看到就再也点不出来。要看得再发一条或去管理页查。

- 来源：SysNoticeServiceImpl.java:58-65
- 确认人：
- 确认日期：2026-11-16
- 状态：待确认

### 关闭状态只存本机，换浏览器或清缓存会重新出现

没有服务端「已读」记录，`notice-closed-<id>` 在浏览器本地存储里。同一个人换设备、换浏览器、清缓存后，同一条公告会再次弹出。

- 确认人：

- 状态：待确认

### latest 接口对任何登录用户开放

首页公告条要在没有后台菜单权限的情况下也能取到公告，所以 `/notice/latest` 没加权限注解。它只返回最新一条已发布公告的标题与正文，不泄露草稿。加权限会导致普通用户看不到公告。

### 「没有公告」和「接口挂了」在页面上无法区分

接口失败是静默 catch，不弹错误、不渲染 DOM，所以首页看不到公告条时，可能是没人发布，也可能是请求失败或被权限拦截，需要看浏览器网络面板或日志才能分辨。

## 怎么验证

- 要准备的：管理员账号（已授权 2750-2754）；`sys_notice` 表已建、菜单缓存已清；至少准备一条草稿、一条已发布，和一条曾发布后下线的记录。
- 主要步骤：
  1. 「系统管理 → 系统公告」能打开；新建草稿显示灰色标签、发布时间为「—」、添加时间有值；改成已发布后变绿色且发布时间为当前时间。
  2. 标题留空、内容留空分别提交：两个输入框下提示「标题不能为空」「内容不能为空」，且没有新增记录。
  3. 首页顶部出现公告条，标题正文换行正确，位于所有 widget 之上；点关闭后消失，刷新不复现；发布一条新公告后重新出现。
  4. 把最后一条已发布公告下线：`latest` 返回 `data=null`，首页不渲染公告条，其他 widget 正常。
  5. 下线后到管理页看，发布时间仍是当初发布那一刻，没有被清空。
- 自动化测试：前端 `pig-ui/src/views/admin/notice/notice.spec.ts`、`pig-ui/src/views/home/notice-bar/notice-bar.spec.ts`；后端 `pig/pig-upms/pig-upms-biz/src/test/java/com/pig4cloud/pig/admin/controller/SysNoticeControllerTests.java`、`pig/pig-upms/pig-upms-biz/src/test/java/com/pig4cloud/pig/admin/service/impl/SysNoticeServiceImplTests.java`（覆盖草稿默认值、发布时间流转、伪造审计字段、latest 过滤、空数组删除）。
