# 我的登录记录

> 一句话：任何登录用户在「个人中心 → 登录记录」标签里看自己最近 30 天的登录记录（时间、IP、浏览器、成功/失败），按时间倒序、可按日期范围筛选，看不到别人的。

代码在 main 上（提交 2473721，分支 agent/T-12），已合并。

## 业务规则

### 只能看自己的：用户名参数只用来识别越权，不参与查库

接口从 `SecurityUtils.getUser()` 取当前登录用户，查库条件永远只用这个用户名。请求里如果带了 `username` 且和当前用户不一致（包括不存在的账号），直接返回空分页，连 service 都不调；一致则照常返回。所以把参数改成别人的名字，拿到的仍是空列表，不会变成「查别人」。

### 窗口硬限最近 30 个自然日（含今天），前端传什么都夹在里面

`WINDOW_DAYS = 30`，`start = max(传入startDate, 今天-29天)`、`end = min(传入endDate, 今天)`；`start > end` 返回空列表而不是报错。前端的日期选择器也把窗口外的日期置灰，两边口径一致，改请求参数也取不到 30 天以前的数据。

- 来源：pig/pig-upms/pig-upms-biz/src/main/java/com/pig4cloud/pig/admin/controller/SysLoginLogController.java:62,106-113、pig-ui/src/views/admin/system/user/components/login-records.vue:56-100

### 只认「登录成功」「登录失败」两类日志，按登录时间倒序

查 `sys_log` 时限定 `createBy = 当前用户` 且 `title in ('登录成功','登录失败')` 才纳入，避免把 `@SysLog` 写进去的业务操作日志混进登录记录。排序固定 `create_time desc, id desc`，请求里的 `descs/ascs` 被丢掉（另建分页对象，只继承页码与页大小），页面不能改排序。

## 接口和数据

- `GET /admin/login-log/page`：分页查询当前用户自己的登录记录。参数 `current`、`size`、`username`（可选，仅用于越权判定）、`startDate`、`endDate`（`yyyy-MM-dd`，可选）。返回 `Page<LoginRecordVO>`，records 每项四个字段：`createTime`、`remoteAddr`、`browser`、`result`（`success`/`failure`）。
- **没有 `@HasPermission`**：登录即可访问，普通用户不需要 `sys_log_view`。
- 数据来源 `sys_log`：`create_by` 是归属依据，`title` 区分登录成功/失败，`remote_addr` 是 IP，`user_agent` 解析成浏览器，`create_time` 是登录时间。
- 前端封装：`pig-ui/src/api/admin/loginRecord.ts`。

## 已知限制

### 失败记录的归属是「登录请求里填的用户名」

登录失败日志的 `createBy` 取的是请求参数 `username`（此时还没通过认证）。有人在登录框输入别人的用户名并输错密码，这条失败记录会记到被输入的那个账号名下，账号主人在「我的登录记录」里会看到一次自己没做过的失败登录。对「察觉账号被撞库」其实是有用的信号，但不能当成「一定是本人操作」。

- 来源：pig/pig-auth/src/main/java/com/pig4cloud/pig/auth/support/handler/PigAuthenticationFailureEventHandler.java:83-92,105-121（`logVo.setCreateBy(username)`）；成功日志用的是认证后的用户名，见 PigAuthenticationSuccessEventHandler.java:119

- 确认日期：2026-11-16
- 状态：待确认

## 怎么验证

- 要准备的：一个普通（非管理员）角色账号，该角色已配好能进站点的菜单（但**不要**给 `sys_log_view`，否则验不到「普通用户也能看自己」）；`sys_log` 里该账号有窗口内（今天与 29 天前之间）的成功、失败记录各若干，最好再造一条 31 天前的旧记录。
- 主要步骤：
  1. 右上角用户名 →「个人中心」，抽屉里出现第 5 个「登录记录」标签（在「API 密钥」之后），前四个标签仍正常。
  2. 不筛选：按登录时间倒序，列顺序为登录时间 / IP / 浏览器 / 结果；分页默认 10 条；31 天前那条不出现、也不计入总数。
  3. 选单日范围查询，条数与总数跟着变；点「重置」输入框清空、回到默认窗口。
  4. 日期选择器里选不到 29 天以前和未来的日期，也选不出开始晚于结束的范围。
  5. 抓请求把 `username` 改成别人的名字再发一次：返回空列表（`total=0`、`records=[]`），HTTP 仍 200，不报错。
  6. 失败行是红色「失败」标签、成功行绿色「成功」；Chrome 那条显示「Chrome 120」这类可读名，无 UA 那条显示「未知」。
- 自动化测试：前端 `pig-ui/src/views/admin/system/user/components/login-records.spec.ts`（接口路径、四列顺序、两态标签、空插槽、日期拆分、分页与排序、第 5 个标签、i18n key 集合）；后端 `pig/pig-upms/pig-upms-biz/src/test/java/com/pig4cloud/pig/admin/controller/SysLoginLogControllerTests.java`（越权返回空、默认窗口、夹紧、start>end、丢弃请求排序、失败口径、UA 解析）。
